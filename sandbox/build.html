V1 in one sentence.

Today a bad send is an instant block. V1 adds hold: the agent must not sign, a row appears in an inbox, and a human taps Allow once / Always allow this address / Block.

In scope

  • New decision: hold (plus existing allow / alert / block)
  • Poll endpoint so the agent can wait on Vercel (no long-lived socket)
  • One inbox screen in the signed-in app
  • Timeout: 10 minutes → treat as block
  • Pause and denylist still block immediately (no hold)

Out of scope for V1

  • Slack / email / Telegram send
  • 24/7 chain poller
  • Token (USDC) history
  • Landing-page redesign
  • Stripe
  • Multi-approver roles

How the agent talks to us

POST /api/v1/check
→ { decision: "hold", must_abort: true, approval_id, poll_url, poll_after_ms: 2000 }

GET  /api/v1/approvals/:id   (same Bearer key)
→ still hold  { decision: "hold", must_abort: true }
→ approved    { decision: "allow", must_abort: false }
→ denied/exp  { decision: "block", must_abort: true }

must_abort: true stays true on hold so old agents that only read that flag still refuse to sign. New agents also poll.

Sequence (when you say “build it”)

  1. Schema. New migration 0005_approvals.sql: table pending_approvals (id, user_id, agent_id, to_address, value_usd, reasons jsonb, status, expires_at, decided_by, decided_at). Status: hold | allow | always | block | expired.
  2. Policy. Extend src/lib/policy.ts verdict with hold. Do not silently change pause/denylist.
  3. Check path. In src/lib/server/intent.ts, if verdict is hold: insert approval row, return decision: "hold", still write a presign transaction with status held. Do not mark the agent critical until timeout or Block.
  4. Poll route. New src/routes/api/v1/approvals.$id.ts. Same API key as check. Expire rows on read if now > expires_at.
  5. Operator actions. Server functions: listApprovals, decideApproval. Always allow → append address to that agent’s allowlist, then allow this id.
  6. UI. New signed-in page /inbox (not the public landing). Three buttons only. Badge on nav with open count. No marketing copy.
  7. MCP. Document that check_transfer may return hold; add get_approval tool. Old agents that ignore hold still see must_abort: true.
  8. Tests. Unit: hold vs block matrix. Integration: check → poll hold → allow once → poll allow. Timeout path. Allowlist append. Pause still blocks.
  9. Do not change src/routes/index.tsx (landing) in V1 unless you later ask for the Sky Ledger design.

Definition of done

  • A live agent hitting an unknown address gets hold, not a silent abort with no next step.
  • Operator can clear it in under 10 seconds from /inbox.
  • Always-allow means the next send to that address is allow without a human.
  • Landing page, billing, and chain ingest behave exactly as today.
  • Tests for hold / allow / block / timeout are green.
